# 吃什么网页版

以用户指定的微信开发者工具当前项目 **0.1.39-alpha** 为基线，将17个页面、3个组件及其业务逻辑适配到浏览器。入口为 eatwhat.pro；不修改原微信工作区，也不使用已经落后于线上版本的 `apps/wechat` 作为本次复刻来源。

## 页面与平台适配

- 首页、口味偏好、食堂决定、档口与菜品筛选、公共评分、历史记录、设置及隐私沿用当前小程序内容、菜单和规则。
- 附近餐厅、地点搜索、真实餐厅决策、详情和路线调用现有自有API；第三方餐厅事实、顺序、有效期、取消和数据授权边界保持原有逻辑。
- 外卖截图支持本地选图、预览、键盘或拖动裁剪、受限分片及原有逐次同意流程。图片只驻留浏览器内存；移除、离开页面或撤回同意时释放，不修改设备原图。
- 手机号/邮箱使用正式 `WEB` 会话。小程序微信登录和原生QQ登录在浏览器关闭；已绑定身份不被改写。旧客户端请求 `includePlatforms=ALL` 时仍只收到其能解析的平台，网页单独请求 `ALL_WITH_WEB`。
- 微信地图组件在网页显示实际道路点构成的路线示意图与分步说明，**不含地图底图**；外部导航由用户主动打开高德地图网页。浏览器定位须用户主动操作和授予权限。
- 页面支持鼠标、触摸、键盘、深浅主题、减少动态效果、安全区和窄屏。浏览器尺寸检查不能替代真实手机定位、软键盘与触感验收。

收藏、账号历史、私有反馈和导出等入口继续按服务端能力显示，不把线上关闭的能力假装为可用。未使用虚构餐厅、菜品或价格填补接口结果。

## 来源与构建

`source/wechat/` 是原始运行输入快照，`source/manifest.json` 固定158个文件的SHA-256。它包含当前项目尚未合并到main的页面与业务实现。构建先逐文件校验快照，再编译WXML表达式和WXSS，并仅应用明确的浏览器账号、图片清理和平台文案转换；没有运行时 `eval` 或动态下载的代码。

`runtime/` 实现增量DOM、Page/Component生命周期、路由历史和浏览器平台接口。原始快照不要直接编辑；更新基线时重新审计并生成清单。`scripts/copy-adapter.cjs` 对可见文案按文件精确转换，保留其他客户端身份标签。

```powershell
pnpm.cmd --filter @eatwhat/web check
pnpm.cmd --filter @eatwhat/web test
pnpm.cmd --filter @eatwhat/web build
pnpm.cmd --filter @eatwhat/web dev
```

预览地址 `http://127.0.0.1:4173`。开发服务器只监听回环；`/api/v1` 转发至固定 `https://api.eatwhat.pro/v1`，不接受外部代理目标。在线业务仍使用真实服务及其限流，不能把本地预览当作隔离测试后端。

单元测试包含合成DOM、平台和请求替身，用于验证生命周期、焦点、手势、数据边界和错误处理；实际浏览器与真实API验收需单独记录。

## 发布与回退

网站发布先运行 `scripts/package-site.cjs`，将资源放入内容指纹目录，首页只引用绝对资源路径。它不覆盖已有包、不依赖HTML base标签，不替换旧站的资源或法律/支持页面。上线时必须从活动网站完整复制形成新候选，核对旧文件保持、完整资源哈希和原页面HTTP响应，再原子切换 `current`。

主站Nginx通过 `scripts/prepare-nginx.cjs` 从已核实的现行双vhost配置生成候选：同源代理以校验过证书的回环TLS复用API全部限制；保留原始URI、上传限流、错误契约、无缓存与无临时落盘边界。仅信任回环来源的代理客户端IP，主站强制覆盖转发头，外部请求不能自报可信IP。应用文档CSP禁止动态求值和base标签，主站定位权限限定为self。安装前必须核对源哈希、备份双配置、执行完整 `nginx -t`，失败同时恢复配置与站点指针。

本次WEB会话补丁基于逐文件核实的**实际线上API**，不是main中的旧服务；源码候选、17迁移、ACL验证与恢复包说明见 [server-patches/README.md](server-patches/README.md)。不能把旧API整包部署覆盖线上，也不能在17迁移后回滚到只能接受16迁移的旧镜像。

合并仍须完成根目录完整 `scripts/verify.ps1`、当前HEAD的push/PR检查及合并后的main检查。实际发布结果、构建摘要和设备未验证项由交付记录另行说明。
