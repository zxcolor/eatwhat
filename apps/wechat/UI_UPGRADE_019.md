## 交互落点

| 位置 | 实现 |
| --- | --- |
| 首页 | 米白背景、既有暖色品牌、明确“帮我决定”、虚拟地点、当前条件摘要；胶囊导航指示块、按钮按压及触点内水波。 |
| 筛选抽屉 | 顶部拖关闭、正文独立滚动、固定操作区；预算和虚拟距离气泡跟手，口味条件、摘要与真实可选数量同步；取消丢弃草稿，应用保留已确认口味。 |
| 候选浏览 | 真实合格候选的目录预览、原生 swiper 吸附、叠卡与展开比较；浏览不消耗推荐、不写确认事件，也不假定随机的下一家。 |
| 结果揭晓 | 真实结果就绪后，从首页触点圆形揭晓；现有餐点示意放大，下方信息卡上推覆盖图片下缘。没有可授权实物照片时明确使用示意。 |
| 换一家 | 横向拖拽按距离、速度与方向判断，未达阈值弹回；旧卡侧向退出，实际新卡补位，名称、价格、距离和理由绑定同一候选。 |
| 确认 | 只有真实 `decision.confirm` 成功且候选与版本一致后，胶囊按钮缩圆并绘勾；渲染完成前和换卡期间不能确认旧卡。 |
| 收藏、历史与设置 | 使用已有查看、移动、删除与重试能力，统一卡片、空态、真实加载骨架；新增可持久保存的“减少动态效果”设置。现有收藏没有创建入口，因此未伪造收藏成功动画。 |

主要过渡使用 transform、opacity 和圆形 clip-path。按压约 140–150ms，状态变化约 240ms，卡片与结果抽屉约 320ms；拖拽回位使用可中断弹簧。关闭、隐藏或换代会清理过期计时器。减少动态效果时简化位移与遮罩，并保留 CSS 系统偏好兼容。

## 数据与范围

- 主流程仍为现有虚拟目录：1092 份套餐、363 家餐厅。价格、距离、候选数量和确认状态均使用实际本地结果；营业状态、配料等缺失信息明确标为未知。
- 未改变核心算法、研究结论、接口契约、真实定位授权或账号隐私边界。虚拟选择不会变成真实订单、已吃记录或账号收藏。
- 真实附近服务继续使用已有授权、失败、重试与恢复入口；本次没有以真实 GPS 或账号服务验收替代本地 UI 验证。
