# EatWhat 微信小程序

2026-10-17 在微信开发者工具中以 **JS 基础模板 / 不使用云服务** 新建的原生小程序。独立目录为 `apps/wechat`；未读取或复用历史 `apps/miniprogram` 实现。

当前本地候选为 `0.1.23-alpha`。MiMo食堂决策接入代码已加入，默认不开启；详情见[MiMo接入说明](../../docs/MIMO_CANTEEN_INTEGRATION.md)。2026-10-21已完成启动所需的API编译和本机真实MiMo调用；尚未完成完整验证或部署公网服务。首启问卷仅有两条滑条：辣度 `spicyLevel` 为 0–6 的七档整数，口味轻重 `flavorIntensity` 为 0–100。两条都主动拖动后才显示「进入首页」按钮，点击并完成本机保存确认后进入首页；预设显示值不等于已经回答。问卷不再收集喜欢或避开类型、预算、价格或距离取舍。本机偏好采用 schema 2，旧五字段问卷不自动映射，需重新完成两条滑条并确认。食堂与虚拟决定共用确认门禁，重新编辑、清除或过期后停止使用旧确认和旧结果。

问题页正文为「请选择你的口味」，顶部导航标题与首页共用北京时间时段规则。第一条初始为「不辣」，只在「特辣Ultra」时启用紫色文字和炫彩填充，其余为蓝色；第二条轨道始终为蓝色，不显示数值，以「清淡」「重口味」端点文字反馈拖动方向，活动端变紫并轻微横向晃动。两个控件均无闪电与重置图标，白色粒子以不同速度连续向左流动；减少动态效果时停用粒子与晃动。0—100 原始数值仍完整保存。

真实食堂菜单暂未提供辣度与口味轻重属性，因此这里只保存这两项声明，不声称已按它们精细筛选或排序。虚拟目录仅将 `spicyLevel=0` 对应到已有的 `maxSpicy=0`；1–6 档完整保存，不编造到旧 0–3 量表的映射。口味轻重也不换算成未提供的菜品属性。虚拟决定采用固定基础排序，价格与距离权重不是用户在这份问卷中的选择；其他流程已有条件功能保留。

首页顶部导航标题按固定北京时间（UTC+8）显示：00:00–10:59「今天早上吃什么」、11:00–16:59「今天中午吃什么」、17:00–23:59「今天晚上吃什么」。进入页面时立即刷新，停留期间每分钟重算，隐藏或退出后停止计时。正文保留「帮你决定这一餐」，位置入口为「虚拟地图」，浅色页面背景为纯白。

首页决策按钮在原处打开推荐底部面板，保留首页上下文；结果、价格和虚拟距离优先展示，依据按需展开，主要未知项直接可见。确认成功后显示已选定状态；关闭、离开页面或偏好失效会停用旧卡片事件。新偏好页通过两条滑条直接完成声明与保存，不再使用旧多步问卷或最终摘要页。

决定仍使用 R9A 复核后的 363 家虚拟餐厅、1092 份套餐，默认套餐模式；主流程不联网、不读取真实位置、不要求登录，账号服务保留。沿用纯白首页、紧接主标题且靠左的地点入口与线条箭头。保存两项口味声明不表示目录已经具备对应属性、完成个性化排序、训练个人模型或认证真实满意度。研究接入、数学适配范围、数据来源与检查方法见 [虚拟决定说明](./DECISION_RESEARCH.md)。

## 微信登录与多端账号

微信登录采用用户点击后的 `wx.login`，临时 code 以 JSON POST 传给 `/v1/auth/wechat-miniprogram/login`。
服务器以固定小程序 AppID / AppSecret 调用 `code2Session`，按既有开放平台 realm 的 UnionID HMAC 找到同一个吃什么账号，再签发 `MINIPROGRAM` 会话。

新通道由独立 `authCapabilities.wechatMiniProgramEnabled` 控制；旧服务缺少该字段时关闭入口。
Android 原生 OAuth 接口保留原语义，不能接收小程序 code；小程序没有 QQ 登录入口。
小程序与安卓必须绑定到同一微信开放平台账号。UnionID 缺失、未关联、原绑定撤销或账号非活动时不建立会话，也不自动创建第二个账号。

服务端专属配置：`WECHAT_MINIPROGRAM_AUTH_ENABLED`、`WECHAT_MINIPROGRAM_APP_ID`、`WECHAT_MINIPROGRAM_APP_SECRET`、`WECHAT_MINIPROGRAM_AUTH_TIMEOUT_MS`；复用 `WECHAT_OPEN_PLATFORM_REALM_ID`。启用前需 schema 0014 与最小权限验收。密钥不得进入小程序目录或聊天记录。
