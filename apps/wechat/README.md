# EatWhat 微信小程序

2026-10-17 在微信开发者工具中以 **JS 基础模板 / 不使用云服务** 新建的原生小程序。独立目录为 `apps/wechat`；未读取或复用历史 `apps/miniprogram` 实现。

当前本地候选为 `0.1.20-alpha`，承接已有 `0.1.19-alpha` 首页位置与交互成果，新增固定真实菜单的「食堂吃什么」。食堂可从首启引导直接进入，不要求口味偏好、定位、登录或联网。原有虚拟餐厅流程继续先选择喜欢与避开的餐厅类型、预算、辣度及决定时的取舍；每次回答后更新就绪判定，只有偏好完整、能实际区分当前可行选择或由明确条件筛出唯一选择，并完成本机保存确认，才进入决策首页。资料不足、无法区分或没有可行选择时继续停留问题页，重新编辑也立即关闭原有决策入口，直到再次确认。

首页顶部导航标题按固定北京时间（UTC+8）显示：00:00–10:59「今天早上吃什么」、11:00–16:59「今天中午吃什么」、17:00–23:59「今天晚上吃什么」。进入页面时立即刷新，停留期间每分钟重算，隐藏或退出后停止计时。正文保留「帮你决定这一餐」，位置入口为「虚拟地图」，浅色页面背景为纯白。

首页决策按钮在原处打开推荐底部面板，保留首页上下文；结果、价格和虚拟距离优先展示，依据按需展开，主要未知项直接可见。确认成功后显示已选定状态；关闭、离开页面或偏好失效会停用旧卡片事件。偏好最终确认页集中展示摘要与真实就绪说明，勾选反馈只反映实际选择和就绪状态。

决定仍使用 R9A 复核后的 363 家虚拟餐厅、1092 份套餐，默认套餐模式；主流程不联网、不读取真实位置、不要求登录，账号服务保留。沿用纯白首页、紧接主标题且靠左的地点入口与线条箭头。这里的个性化是用户明确声明驱动的规则排序，不表示已训练个人模型或已认证真实满意度。研究接入、数学适配范围、数据来源与检查方法见 [虚拟决定说明](./DECISION_RESEARCH.md)。

## 食堂吃什么（0.1.20-alpha）

首页地点入口下方新增「食堂吃什么」卡片；首启口味引导也有「直接去食堂吃什么」，无需先完成虚拟餐厅偏好。历史页签和设置提供「食堂选择记录」。原有餐厅、套餐、位置和账号入口保留。

菜单仅依据用户提供的 [餐品清单](../../docs/canteen/餐品清单.md)，未查看或核验清单引用的原图。8 个档口分别录入 9、14、25、26、21、15、3、30 条，共 143 条。菜单 JSON 保存稳定 ID、原分类、原始名称、完整标价文字、整数分金额、原单位、规格、备注和来源链接；未标明单位时保持 `null`。

| 文件 | 作用 |
| --- | --- |
| `data/canteen-menu.json` | 唯一结构化来源菜单，含全部 143 条 |
| `data/canteen-policy.json` | 每条是否进入默认池的显式产品配置 |
| `data/canteen-menu.js`、`data/canteen-policy.js` | 由 JSON 生成、供微信运行时直接读取的镜像；检查脚本核对一致性 |
| `lib/canteen-decision.js` | 独立候选过滤、按菜品等概率抽取、本轮 ID 去重、规格选择与确认凭据 |
| `pages/canteen/` | 食堂筛选、结果、换菜、确认、空集与耗尽交互 |
| `lib/canteen-records.js`、`pages/canteen-records/` | 主动开启后保存本机选择，含规格、标价与时间 |
| `app.js`、首页、偏好引导、设置与隐私页 | 路由接入、入口、记录清理和说明 |

默认候选为 124 条，明确排除山东煎饼 8 条加料、福建风味 9 条米线浇头及 2 条豆浆；不依据菜名猜测、不组合套餐。5 个多规格条目每道菜只占一个抽取位置，结果展示真实大小份价格，确认前必须选择符合预算的规格。3 个称重条目保留「素菜1.2元/50g；荤菜2.8元/50g，均价14」，没有固定总价；任何严格预算上限都会排除它们。

本轮在符合条件且未展示的菜品中均匀抽取。不同档口同名商品独立，换菜按菜品 ID 去重；条件改变立即清旧结果并开新一轮。候选耗尽后由用户明确重新开始，空集不自动放宽条件，单候选仍可确认。连续点击有短锁，旧页面事件和旧规格事件不能覆盖新状态。沿用现有卡片、占位图与动效时长；减弱动画不影响防连点保护。

食堂不接入独立 Algorithm 项目或现有研究排序，不发起食堂网络请求、定位或登录。记录默认关闭，主动开启后最多保留 30 条、90 天，不上传或关联账号。确认多规格保存实际规格与标价；称重记录的金额为 `null`，不是付款记录。关闭即清除，撤回隐私同意也清除记录和启用选择。清理失败会阻止继续写入，并在退出、重新进入两个食堂页面后保留重试提示。

原始资料没有阻塞本次录入的问题。同名跨档口商品、两款牛肉米线、卤蛋双用途以及未注明单位均按原文保留；原图、当日售卖情况与现价仍未核验，不能由本地校验推导。

## 微信登录与多端账号

微信登录采用用户点击后的 `wx.login`，临时 code 以 JSON POST 传给 `/v1/auth/wechat-miniprogram/login`。
服务器以固定小程序 AppID / AppSecret 调用 `code2Session`，按既有开放平台 realm 的 UnionID HMAC 找到同一个吃什么账号，再签发 `MINIPROGRAM` 会话。

新通道由独立 `authCapabilities.wechatMiniProgramEnabled` 控制；旧服务缺少该字段时关闭入口。
Android 原生 OAuth 接口保留原语义，不能接收小程序 code；小程序没有 QQ 登录入口。
小程序与安卓必须绑定到同一微信开放平台账号。UnionID 缺失、未关联、原绑定撤销或账号非活动时不建立会话，也不自动创建第二个账号。

服务端专属配置：`WECHAT_MINIPROGRAM_AUTH_ENABLED`、`WECHAT_MINIPROGRAM_APP_ID`、`WECHAT_MINIPROGRAM_APP_SECRET`、`WECHAT_MINIPROGRAM_AUTH_TIMEOUT_MS`；复用 `WECHAT_OPEN_PLATFORM_REALM_ID`。启用前需 schema 0014 与最小权限验收。密钥不得进入小程序目录或聊天记录。

已有数据库升级和通道启用顺序见 [schema 0014 上线门禁](../../docs/wechat-miniprogram-cutover.md)。
