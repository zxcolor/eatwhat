# 同设备匿名群组决策架构

> 产品范围（2026-09-12）：只服务一个人的用餐决策，永久取消多人用餐。历史群组方案与验收记录仅作追溯，不属于当前或未来待实施功能。

## 状态与目标

本文定义 Android 2.x 的首个本地安全切片 `GROUP_CONSTRAINT_INTERSECTION_V1`。它是工程候选规范，
不代表生产开关、真实供应商授权、完整目标设备矩阵或公开发布已经完成。

目标是在同一台手机上让 2–8 位参与者依次填写结构化约束，由服务端重新计算一套共同条件并返回
最多 3 个只读候选。该能力不是多人房间，也不是把现有 `partySize` 改名：`partySize` 仍表示一套
条件对应的就餐人数；群组决策则包含多份互相独立、只在当前进程内存在的成员约束。

## 明确包含

- 一个由组织者选定的共同出发点和共同交通方式。
- 2–8 份匿名成员约束：预算上限、可用时间、最远距离、偏好菜系和排除菜系。
- 固定的普通午餐、无主动体感、平衡探索、默认偏好向量和确定性规则路径。
- 服务端重算、回显并由 Android 再次核对的版本化共同条件摘要。
- 最多 3 个只读候选，以及每个候选的可核对理由、风险提示和来源标识。
- 按相同共同条件重新请求；结果可能相同，不承诺跨请求反重复。

## 明确排除

- 房间、加入码、邀请链接、二维码、跨设备同步、轮询、WebSocket、推送或附近设备发现。
- 对餐厅的投票、评分、点赞、实时广播或成员满意度/公平度分数。
- 姓名、昵称、头像、成员 ID、组 ID、设备 ID、账号 ID、自由文本或每位成员的位置。
- 登录、账号画像、个人偏好向量、天气或体感、早餐/晚餐和奶茶/咖啡/甜品专项。
- DataStore、SavedStateHandle、Bundle、磁盘缓存、服务端数据库、决策历史或其他持久化。
- 千问或其他模型、推荐事件、收藏、私有反馈、详情、导航、拨号、复制地址和分享。
- 稳定 POI ID、`resultToken` 或可兑换成服务端地点引用的任何句柄。

## 请求与聚合

请求只包含一个共同 `Coordinate`、`WALK | BIKE | TRANSIT` 交通方式和 2–8 份严格成员对象。
成员对象中的预算为 `null` 或 1–2000 元，可用时间为 15–240 分钟，半径为
200–10000 米；偏好与排除项各自唯一且最多 8 项，同一成员不得同时偏好和排除同一菜系。
任何未知字段都必须由服务端共享契约拒绝。

服务端不得信任客户端提交的聚合值，必须按以下版本化算法重新计算：

1. 成员数等于请求数组长度。
2. 预算取全部非空上限的最小值；全部为空时才为不限。
3. 可用时间和最远距离分别取最小值。
4. 排除菜系取并集。
5. 偏好菜系忽略空集合后取交集，再减去排除并集；输出使用契约枚举的固定顺序。
6. 内部推荐上下文固定为普通午餐、`GUIDED`、`BALANCED`、无体感、默认偏好向量、AI 关闭。
7. 营业时间判断只使用服务端当前时间，不接受客户端时间。

算法必须满足成员排列置换不变性。任一成员的排除项形成共同硬约束，这叫约束求交，不得在界面
或指标中表述为“一票否决投票”。现有推荐引擎中的时间仍是可行性信号和警告，不得宣传为绝对
硬过滤。

## 响应与数据权利

多人响应使用独立的 display-only schema，不复用普通推荐公开响应。它只包含单次响应 UUID、生成
时间、全国覆盖标识、数据权利模式、规则版本、共同条件摘要、最多 3 个收窄后的展示结果和可选
说明。

结果不得包含 `resultToken`、`actions`、坐标、电话、图片 URL、`aiAssisted` 或任何 AI/model/prompt
字段。普通推荐的短期 token registry 不为群组请求签发条目，因此事件、收藏、历史和反馈接口没有
可兑换的群组地点引用。

`LIVE_DISPLAY_ONLY` 只做本次请求的合法查询、硬过滤和数据源原始顺序展示，所有 `fitScore=null`；
界面只称“首个候选/其他候选”，不称主推荐、排名或平台替用户选定。只有现有逐供应商授权门禁
实时确认 `LICENSED_ENRICHMENT` 时才可使用透明自有排序；即使如此，也不得声称代表每位成员的
满意度或公平性。

## 能力门禁与失败关闭

`GROUP_RECOMMENDATIONS_ENABLED` 默认 `false`。`/v1/config` 只有在以下条件同时成立时才把
`serviceCapabilities.groupRecommendationsEnabled` 明确返回为 `true`：

- 群组环境开关明确开启；
- 普通推荐核心能力可用；
- 当前 provider 明确支持 `MEAL/LUNCH/NONE` query plan。

旧 v1 配置缺少新增字段时客户端必须按 `false` 处理。多人端点本身仍需独立重复检查开关与
provider 能力；关闭、不支持或探测抛错时必须在 provider 和 AI I/O 前统一返回 503。远程配置不可用
时不得借用游客规则推荐 fallback。默认 ECS、Debug 和 Alpha 均不因代码存在而自动开放该能力。

## Android 内存与生命周期

Android 使用独立、Activity 作用域的 `GroupDecisionViewModel`。它不得注入 `SavedStateHandle`、
`AppPreferences`、历史、账号、收藏或反馈仓库。路由不携带位置、成员约束、餐厅、请求 ID 或响应。

- 旋转等配置重建可继续使用同一 Activity 级内存 ViewModel。
- 可信配置 generation 改变、最低版本提高、隐私撤回、显式退出、真正退到后台或进程死亡时，
  必须取消在途任务并清空成员输入和结果。
- 晚到响应必须同时通过本次群组请求 generation 和进程级远程访问 lease 复查。
- Android 必须独立重算摘要并逐字段匹配服务端回显；版本、聚合、顺序、硬约束或数据权利不符
  时拒绝展示。

## UI 状态与文案

入口只在可信兼容配置明确开放群组能力时出现。用户先在首页选定共同地点，再进入无参数内部路由。
流程为：设置人数与共同交通方式、按“第 N 位/共 M 位”轮流填写、共同条件复核、加载、结果或失败。
最后一位完成前不得出现餐厅候选，避免流程演化为逐人投票。

界面必须持续说明“同一台手机轮流填写，不创建房间或账号”。成员输入只能使用选择器、步进器或
固定枚举，不提供姓名或自由文本框。结果页只提供“按相同共同条件重新请求”和“返回重新录入”，
不注册详情或任何出站动作。

## 最低验证矩阵

- 契约：1/9 人拒绝、2/8 人接受、未知或身份/自由文本/成员位置字段拒绝、响应敏感字段不存在。
- 聚合：预算 null/最小值、时间/半径最小值、排除并集、非空偏好交集、排除优先、固定顺序、
  成员置换不变。
- API：能力默认关闭、provider 不支持或抛错时零 I/O、Qwen 永不调用、服务端时间覆盖、token
  registry 不增长、LIVE 顺序和 `fitScore=null`。
- Android：旧配置缺字段为 false、直接路由失败关闭、2–8 人状态机、摘要双算、代际变化/后台/
  隐私撤回/退出清理、晚到响应丢弃、无持久化依赖。
- 设备夹具：同设备轮流填写到只读结果，验证请求无 Authorization、姓名、ID、自由文本、成员位置、
  AI/天气字段，响应界面无详情、动作、保存、事件和分享入口。

2026-09-04，独立临时 API 36 / Pixel 6 模拟器 `emulator-5560` 已通过群组设备内合成 API 的
3 个 `@Test`：完整提交、Activity 配置重建保留进度、真实后台返回后清空且不提交。严格运行器
返回 `OK (3 tests)`、退出码 `0`，并完成端口映射恢复；不访问真实 provider 或生产服务。

生产开放还需要 API 26–36 目标设备矩阵、无障碍、弱网与跨设备型号后台恢复验证，并按供应商、数据权利、合规与发布门禁
单独验收；代码和 DEMO 通过不能替代这些外部证据。
